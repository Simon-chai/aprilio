## 自定义宠物接入：架构 + 原型 + 素材工作流

### 架构定案（`docs/DESKTOP_PET.md`，AGENTS.md 索引 + ROADMAP 已更新）

三层，**Live2D 不与宠物本体绑死**（相对 2026-09-09 选型记录的关键推进）：

1. **宠物包** `pet.json`：`runtime` 决定渲染方式，换宠物 = 换包，不改代码，存 `appLocalDataDir/pets/<id>/`
2. **PetRuntime 适配器**：`mount / setState / setParams / destroy`，参数对齐 Live2D 参数 ID
3. **事件桥**：`AgentEvent`（text-delta / tool-start / tool-end）→ 状态机 + 逐帧插值

阶段：P0 原型（已完成）→ P1 vector-layered + sprite 适配器 + Rust 三条命令 → P2 live2d → P3 形象授权。

### 素材规范要点（DESKTOP_PET.md §10-11）

- 画布 512×512，中心线 x=256，脚底线 y=478，上下留 ≥30px 防动作裁切
- 图层 id：`pet-root` / `pet-head` / `pet-eye-l,r` / `pet-mouth` 必需；
  `pet-body` / `pet-tail` / `pet-ear-l,r` / `pet-blush-l,r` / `pet-shadow` 可选
- 表情变体：`pet-eye-open|happy|sleep-*`、`pet-mouth-closed|open`、`pet-tongue` —— 显隐切换优于几何变形
- 旋转锚点：`data-pivot="x,y"` 声明；缺省按包围盒推断。眼睛/嘴要用**基准元素**
  （`pet-eye-open-*` / `pet-mouth-open`）算包围盒，否则隐藏变体会把中心拉偏
- 三条路线成本：矢量 2~6 小时 / 位图帧 1~3 天 / Live2D 1~2 周

### 工程经验（可复用）

- **本地单文件 HTML 原型的验证套路**：抽 `<script>` 跑 `node --check`；再用 jsdom
  `runScripts:"dangerously" + pretendToBeVisual` 加载后断言（挂载 / 数量 / 事件 / DOM 属性变化）。
- **jsdom 不实现 SVG `getBBox` / `getScreenCTM`**：用 `beforeParse` 注入简化 getBBox
  （支持 ellipse / circle / rect / line 并递归合并子元素）即可验证锚点推断；
  产品代码里 `getBBox` 一律走 `safeBBox` 兜底，取不到就跳过相关校验。
- 装配台用「外层包 wrapper `<g>`」承载所有 transform，避免覆盖素材原有的 transform 属性。
- **同一次消息里对同一文件并行 Edit 会互相覆盖**（上一轮踩过，本轮一律串行或整体重写）。
- 装配台的内嵌模板用占位符 + 注入脚本同步，避免手抄两份不一致。

## 贴图素材路线 + 贴图装配台（用户追问「只能用 SVG 么，有没有更精细的贴图素材」）

### 素材精度阶梯（`docs/DESKTOP_PET.md` §10 重写）

| 路线 | runtime | 精度上限 | 成本 |
| --- | --- | --- | --- |
| 分层矢量 | `vector-layered` | 扁平插画 | 2~6 小时 |
| **分层贴图** | `raster-layered` | **手绘 / 厚涂 / 3D 渲染** | 1~3 天 |
| 序列帧 | `sprite` | 同上，动画更自由 | 1~3 天 |
| Live2D | `live2d` | 带网格形变、可转头 | 1~2 周 |

**分层贴图的核心约定：所有图层导出时保持同一画布尺寸与位置**（Spine / Live2D 通行做法），
叠加即原图，导入零对齐成本；逐层裁切 = 手工对齐地狱。

### `prototypes/pet/pet-raster.html`（新增）

- 拖入分层 PNG → 按文件名自动识别部位（`body.png`→`pet-body`、`left-eye-open.png`→`pet-eye-open-l`）
- 同尺寸自动原位对齐；散图给初始尺寸后手动摆位
- DOM 按语义嵌套（眼在头里、嘴变体在嘴里），每层 img 独立 left/top/scale/rot/z/opacity
- 关节变换：root 绕脚底线、head/tail/ear 绕各自锚点、pupil 平移做视线、眼与嘴的变体显隐
- 「生成演示图层」：内嵌矢量模板逐层 isolate → SVG 转 canvas → PNG，无需自备素材即可看效果
- 暴露 `window.__petRaster` 自动化钩子（inject / rebuild / setState）供冒烟测试

### 踩到并修掉的坑

- **变体缺失导致眼睛消失**：素材只有笑眼没有睡眼时，切到 asleep 会四层全 opacity 0。
  改为**按左右眼分别判断**——缺对应变体就退回常态眼（`eff = 'normal'`），
  保证「任一时刻恰好一个眼睛形态可见」，冒烟断言 `sum(open+happy+sleep) === 1`。
- **透明度管理冲突**：普通层每帧写 `L.opacity` 会覆盖变体层显隐，改为变体层与腮红层跳过位置/透明度阶段。
- **文件名 `left-xxx` 映射**：原本替换成 `l-xxx` 查表失败，改为 `xxx + '-l'` 再查表。
- jsdom 无 canvas：`getContext('2d')` 返回 null 时直接 `cb(null)`，演示生成降级不崩。
- 模板 `layered-cat.pet.svg` 的 `pet-face` / `pet-nose` 由散装元素收成组，
  否则逐层导出贴图会丢细节（脸只剩深色底、鼻子丢高光）。

## AI 出图 → 素材板切片（用户要「一张图生成多个素材」）

### 提示词手册 `prototypes/pet/AI_PROMPTS.md`（新增）

一张 3×3 素材板，9 格固定顺序：身体 / 头（不含耳） / 尾 / 睁眼 / 笑眼 / 睡眼 / 闭嘴 / 张嘴 / 单耳。
眼睛耳朵只画一侧，靠镜像补另一侧。背景要有角色配色里不存在的纯色（暖色角色用品红 `#FF00FF`，
粉紫角色用绿 `#00FF00`）。含中英文主提示词、负面词、5 种风格块、3 个完整示例、参数建议、
逐部件 img2img 进阶、生成后验收清单。

### `pet-raster.html` 新增「素材板切片」（`SHEET_ORDER` / `MIRROR_SLOTS` / `SHEET_LAYOUT`）

- 拖入素材板 → 4 角自动取背景色（截尾均值，防某角被角色压住）+ 按角间色差推荐容差
- 行列可调（≤6×6），顺序清单实时显示每格映射，网格辅助线叠加在预览上
- **抠图不是 RGB 距离，是 YCbCr 色度距离**：纯品红和白色的 RGB 距离只有 0.58，
  抗锯齿边缘会留紫边；改成「色度平面上像素到背景色度的距离 ÷ 背景色度模长」，
  这个值在混合场景下近似等于前景覆盖率（50% 白 + 50% 品红算出 0.502），可直接当 alpha，
  再用 alpha 反解前景色（unmultiply）去掉边缘色溢。
- 抠完按内容紧裁（bbox of alpha>12），再按 `SHEET_LAYOUT` 骨架粗摆位（比例取自 `layered-cat.pet.svg`）
- 眼/耳/腮红/爪自动水平镜像补另一侧（canvas 翻转，不是复制）
- **画布锁定 512**：`canvasMeta.locked`，否则 `resetCanvas` 会按最大图层把它缩掉
- pet.json 的 `canvas.align` 分两种语义：`same-size`（逐层等大原位）vs `placed`（自然尺寸 × scale，中心在 x/y），
  切片路线输出 `placed`

### 踩到并修掉的坑（切片器）

- **`var` 重名导致半透明像素污染其后全部像素**（最坑的一个）：去色溢分支写了 `var k = 1 - af`，
  把外层的「本格增益 k」冲掉，于是**扫描顺序上第一个半透明像素之后的所有像素都按增益≈0 被抠成透明**，
  表现为切片结果从某像素起整片消失。改名为 `back` 并加了顺序回归测试。
- **色度距离的上限取决于前景色自身色度**：紫配品红时 q 顶多 0.71，整块部件只有 71% 不透明。
  加按格归一化增益 `1/clamp(qMax,0.625,1)`（上限 1.6），实心部分拉满，背景仍在容差下被抠掉。
- **部件放大到固定边长会让 scale 失配**：`makeLayerCanvas` 曾把裁切图放大到固定长边，
  但 `scale` 是按原始裁切尺寸算的，渲染宽度会放大数倍。改为保持裁切分辨率。
- AI 出图原生缺陷：头部提示词里写了「含耳朵」，与第 ⑨ 格「单独一只耳朵」自相矛盾——
  耳朵焊死在头上就做不出耳朵抖动。已改提示词为「头不含耳朵」。

### 测试方法（可复用，重要）

- `prototypes/pet/smoke.mjs`，一条命令跑完：`node prototypes/pet/smoke.mjs`（本轮 73 断言）
- 纯计算部分（抠图数学 / 紧裁 / 镜像 / 摆位）直接单测，不需要 DOM
- **jsdom 没有 canvas**，画布链路（getImageData → 抠图 → putImageData → toDataURL → drawImage）
  要另想办法。两条路都试过：
  - Edge/Chrome 无头 `--dump-dom` 在本机沙箱里静默无输出（stdout 空、exit 0），不可用
  - **可行方案：`@napi-rs/canvas` 垫进 jsdom** —— `beforeParse` 里替换 `document.createElement('canvas')`
    返回原生 canvas、替换 `window.Image` 为垫片（`loadImage` 是异步的，解完再触发 onload）、
    给 context 原型的 `drawImage` 打补丁解包垫片。依赖装在用户主目录 `~/node_modules`（项目零污染）

  （状态泄漏只在多像素连续扫描时显现），必须走完整画布链路才能暴露。
  断言要落在「被切下来的图长什么样」上，而不只是「切出了几层」。

## 拉取远端并解决冲突（用户：「把远端代码拉下来，解决下冲突」）

- 处理：`git merge --no-ff --no-commit origin/main` → 解 AGENTS.md（**保留全部 3 行新索引**：
  设计系统 / 评价报告 / 桌面宠物，都接在背景图库之后）→ 提交 `4acc98c`
- 合并正确性判据：`git diff --stat origin/main HEAD` 应恰好等于本地新增文件（本次 13 个文件 / 5248 行插入），
  多一个都说明远端内容没进来或本地被覆盖

### 大坑：外部工具并发改工作区，导致 rebase 半途崩坏

- `git pull --rebase` 后 108→172 个文件显示 deleted、`src/` 被掏空。
  根因**不是 git**：`refs/cline/checkpoints/*` + 运行中的 `Code.exe` 在并发删改工作区，
  rebase 的 checkout 被从中打断；`git rebase --abort` 也被 SIGTERM 打断，留下
  `.git/rebase-merge` + `.git/index.lock` 陈旧状态；`git branch -f` 建备份分支返回 0 却不落盘
- **恢复序列（有效）**：`rm -f .git/index.lock; rm -rf .git/rebase-merge .git/rebase-apply;
  git checkout -f main; git reset --hard main` → 缺失数归 0
- **判断「文件缺失是外部进程干的还是合并干的」**：看 `git ls-files --deleted` 与 index 是否一致；
  若 index 正确（`git ls-tree -r HEAD | wc -l` 数量对）而磁盘缺文件，
  一条 `git reset --hard HEAD` 即可复原，不必怀疑合并本身
- 结论：**这个仓库跑 git 写操作时，先确认没有 Cline 检查点/编辑器在同时动工作区**；
  用 `--no-ff --no-commit` 而非 rebase，看得见真冲突、也更容易中途恢复
