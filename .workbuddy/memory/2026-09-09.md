# 2026-09-09

## 个人资料持久化 bug 修复（用户报告：编辑保存后重启丢失）

### 根因（三层叠加）

1. **sqlx 迁移 checksum 失配**：用户库 `_sqlx_migrations` 里 v1/v2 的 SHA-384
   与当前 lib.rs 源码不符（v1 SQL 历史上被重写过但库未跟随）。
   sqlx 0.8.6 `validate_applied_migrations` 遇 mismatch 抛 `VersionMismatch`
   → 迁移流程整体中止 → v3–v6 从未被记录/应用（可用 ensureSchema 兜底掩盖）。
2. **tauri-plugin-sql 的 load 语义放大了它**：`commands.rs::load` 对迁移列表
   `remove()`（一次性消费）且 `pool.migrate(...)?` 错误直接让 load 失败。
   → 每次进程启动的**第一次** `Database.load` 必失败；重试时迁移列表已被拿走
   → 第二次 load 跳过迁移**成功** → 之后读写全部正常（写入成功、保存有反馈）。
3. **ensureProfile 静默吞错**：`readProfile().catch(() => ({...DEFAULT_PROFILE}))`
   把首次 load 失败吞掉，重启后的首窗口期 profile 显示默认值 → 用户看到"编辑丢失"；
   若此时在资料页点保存会把默认值写回 DB（自毁覆盖）。

### 修复

- lib.rs：v1 建表并入 `profile.timetable_bg`、v3 并入 `timetables.my_subjects`、
  v4 并入 `calendar_events.title` 并在开头幂等重建 `calendar_memos`（保底搬迁）；
  **删除 v5/v6**（从未被库记录，可安全移除）。
- 用户库一次性修 checksum：UPDATE `_sqlx_migrations` v1/v2（脚本已删，备份在
  `/tmp/aprilio.db.pre-migration-fix.bak`）；v3/v4 由下次启动自动补齐。
- db.ts `getDb()`：首次 load 失败自动重试一次（利用插件 remove 语义，
  第二次必成功），首次失败 console.error 落盘。
- profile.ts `ensureProfile`：readProfile 失败改为 console.error 落盘（不再完全静默）。
- **顺手修了 dev 模式前端全崩的 bug**：docs.ts 的 `import.meta.glob("/docs/*.md")`
  （root 相对）在 Git Bash 小写盘符 cwd（d:\）下生成跨盘符坏 import
  （path.relative 盘符大小写敏感，与 vitest 4 坑同源），改成相对 importer 的
  `../../../docs/*.md`。

### 排查方法论（复用价值）

- checksum 算法：sqlx 0.8.6 = `Sha384::digest(sql.as_bytes())`，纯 SQL 原文。
- 日志在 `%LOCALAPPDATA%\com.tauri.dev\logs\aprilio.log`（Roaming 是 DB），
  时间戳 UTC；日志只有 40KB 轮转不留历史。
- "写入成功但 v3+ 未记录"是 plugin remove 语义的指纹；
  "重启就丢、重进又正常"是首窗口期静默回退默认值的指纹。
- WebView2 前端是否真的加载：看 `_sqlx_migrations` 有没有新记录
  （Database.load 是迁移唯一触发点），比看日志更硬。

### 验证结论

- 673 个 TS 测试全过（含 schema-sync 表名对账）、vue-tsc 过、cargo build（含 tauri dev 的
  --no-default-features 特性集）通过。
- **库副本模拟 sqlx 运行时通过**：validate（v1/v2 修复后 checksum）→ apply v3 OK →
  apply v4 OK（calendar_memos 保底重建→空搬→DROP）→ profile 数据逐字节无损。
  即用户环境正常启动 app 时迁移链自动补齐，VersionMismatch 从此不再发生。
- 本会话无法端到端跑通 WebView 渲染：会话代理（HTTP_PROXY=127.0.0.1:53332）劫持
  WebView 对 localhost 的加载 + WebView2 进程池复用旧环境，属测试环境问题而非产品问题
  （curl 直连 vite / main.ts / docs.ts transform 全部干净；用户环境历史上前端可正常加载）。
- 防御纵深即使再遇迁移异常：getDb 首次失败自动重试（插件 remove 语义下第二次必成功）
  + ensureProfile 失败落盘，"静默回退默认值诱导覆盖保存"的丢失路径已堵死。

## Bing 壁纸支持一次拉多张（用户需求：每日图片不只一张）

- 背景：`fetch_bing_wallpaper` 原来写死 `HPImageArchive.aspx?...&n=1`，只拿当天一张；
  Bing 官方接口 `n` 上限 8（最近 8 天）。
- Rust `backgrounds.rs`：命令加 `count: Option<usize>`（clamp 1..=8），返回
  `Vec<BingWallpaper>`（新→旧，第 0 张是当天）；命令名不变，lib.rs 注册无需改。
- `wallpaper.ts`：`WallpaperConfig` 加 `count`（默认 7）+ `clampWallpaperCount` 兜底脏值；
  主流程分流：当天那张换背景（`last_url` 同图仍只推进日期），其余近期图只回填图库
  （origin_url 去重天然免重复下载），单张回填失败 console.error 跳过、不断流、日期照常推进。
- 设置页加「每次拉取」select（仅当天/近3/5/7/8天）；`docs/BACKGROUNDS.md` 同步。
- 测试：`tests/wallpaper.test.ts` 重写 mock（返回数组、落盘文件名递增），
  新增张数透传 / 同图不换背景但补缺 / 回填单张失败不断流 3 用例。
- 验证：typecheck + 675 TS 用例全过、cargo check 过、backgrounds 单测 3/3 过。
  （cargo test 首跑遇 fingerprint os error 5 文件锁，重试即好，杀软瞬时锁。）

## BongoCat 源码级分析（克隆到 %TEMP%\bongocat-analysis，用户场景：首页右下角 AI 助手宠物形象）

- **核心结论**：BongoCat 的渲染层是 easy-live2d（MPL-2.0，Panzer-Jack）的 141 行薄封装
  （src/utils/live2d.ts），底层 pixi.js 8。剥离成内嵌组件后 **Rust 侧零改动**
  （rdev 设备监听/窗口插件/托盘全不需要），适合"AI 助手形象"而非独立桌宠。
- 依赖仅 2 个 npm 包：easy-live2d + pixi.js；Cubism Core（live2dcubismcore.js）
  **不在任何包里**（Live2D 许可限制），需从 Live2D 官网下载放 public/Core/ 并 index.html 引入。
- 剥离清单：带走 utils/live2d.ts（可再简化）+ 一个 <canvas> Vue 组件；
  扔掉 useDevice/useGamepad/键盘贴图叠加/窗口 scale/托盘/右键菜单（pages/main/index.vue 里 90% 用不上）。
- API 对口 AI 场景：startMotion/setExpression/setParameterValueById('ParamMouthOpenY')，
  easy-live2d 自带 playVoice + lip sync（ai_chat_stream 逐 token 可驱动嘴动）。
- 自定义形象：标准 Cubism 目录（model3.json+moc3+贴图+motion3+exp3）直接可用；
  BongoCat 导入机制=目录 COPY_DIR 到 appDataDir/custom-models（Rust fs_extra），简化版可先打包进 public/models/。
- 版权：BongoCat 代码 MIT；**内置猫模型来自 Bongo-Cat-Mver 社区，授权未豁免**，随应用分发需确认；
  Live2D Cubism SDK 对小规模经营者免费（需附声明、禁逆向）。选模型建议扁平/简约风贴合 Apple 视觉。
- 工作量：POC 半天~1 天（组件+内置模型）；完整（模型切换+表情库+Agent 联动）2~3 天。
  pixi.js ~450KB gzip 建议 dynamic import，助手挂载时才加载。
