# 发版记录与兼容性基线

本文是版本的兼容性基线与发版台账。**自 v1.0.0（第一版发版）起，所有改动必须往前兼容**：
用户升级后，既有数据库、本机存储、导入过的文件与 Agent 调用必须继续可用。

## 兼容性总则

需要守护的兼容面：

| 面 | 说明 |
| --- | --- |
| 数据库结构 | 建表迁移收敛在 `src-tauri/src/lib.rs`（当前是单一初始建表，不做增量迁移）；v1.0.0 起用户库里已有数据，新增字段一律「加列 + 代码兜底默认」，禁止依赖删库重建 |
| 本机存储 | localStorage 键名与 JSON 结构（等级映射、图表偏好、模型配置、背景索引等）；`aprilio.db` 路径与内容；`photos/`、`backgrounds/`、`pets/` 目录约定 |
| 导入 / 导出格式 | 花名册模板、成绩单样例、课表导入的列语义只能在旧口径上扩展，不能改旧列的含义 |
| Agent 接口 | `src/agent/tools/*` 的工具名与参数语义只增不改；应用内 MCP 只读工具面（`src-tauri/src/mcp_server.rs`）同理 |

破坏性变更（确需时）：必须同时提供**迁移或兼容读取**（旧数据自动升级 / 新代码读到旧数据不崩），
并在本文对应版本下登记「破坏性变更」一节。

## v1.0.0 · 第一版发版（2026-09-27）

首个功能完整的发版基线，版本号 `1.0.0`（`package.json` / `src-tauri/tauri.conf.json` /
`src-tauri/Cargo.toml` 三处一致），git tag `v1.0.0`。功能面：

- **学生档案与班级**：班级管理（含归档的历史班）、学生详情（基本 / 监护人 / 照片 / 表现 / 成绩 / 学期）、
  回收站（7 天可恢复）、全局搜索
- **导入**：花名册智能导入（规则 + AI 姓名列；双行分组表头、最多两位监护人与单位/职务合成、忽略列可见）、
  成绩导入（成绩单识别、考试批次幂等、自动建档、档案缺学生即花名册）、课表导入；
  整批无班级信息时由 AI 从文件名 / 标题行推断班级名（如「四8班学生详细信息.xlsx」→「四8班」）
- **成绩**：班级 / 个人成绩面板、五种分布图型、等级映射与「只显示等级」、排名与趋势、
  AI 成绩分析（`analyze` 内置分析器，口径与界面同源）
- **学期化**：成绩 / 表现 / 作业 / 评语按日期自动归属学期，学生详情可切学期回看
- **课程表**：班级全科课表（万年历 + 备忘 + 网格编辑）与「我的课表」按任教学科聚合
- **Agent**：能力容器 + 工具注册表 + 页面动作、写操作确认门、Rig + rmcp 双轨（应用内 MCP server
  只读工具面）、流式输出、RAG 语义搜索（Ollama embedding）
- **课堂模式**：节课 = 会话容器 × 可组合活动 × 统一事件流（v9 四表），崩溃重放恢复
- **界面与体验**：设计系统 token 与 design-token-guard 防退化门禁、背景图库、桌面宠物、评价报告

发版打包时把 bundle identifier 从占位值 `com.tauri.dev` 换成 `io.github.simonchai.aprilio`
（安装包要求全局唯一；同步改了 `src-tauri/src/paths.rs` 的 `APP_IDENTIFIER`）。
数据目录随 identifier 变化（`%APPDATA%` / `%LOCALAPPDATA%` 下的标识层）：
首次启动由 `paths.rs` 的 `adopt_legacy_data_dir` 把旧标识目录**整份接管**到新目录
（数据库 / 照片 / 背景 / 日志，已有文件不覆盖），升级后老数据不丢。

兼容性：本版为基线，无更早的发行版本需要兼容；旧标识数据目录的接管已内置。

## v1.1.0 · 评价卡片、家校沟通总结、提示词管理（2026-10-06）

版本号 `1.1.0`（`package.json` / `src-tauri/tauri.conf.json` / `src-tauri/Cargo.toml` 三处一致）。相对 v1.0.0 的新增内容：

- **学生档案评价卡片**：按周期聚合（成绩/表扬/作业）一键生成图文评价卡片并导出 PNG（foreignObject 零依赖转图，演示态退化为浏览器下载）；机制见 [EVAL_CARD.md](EVAL_CARD.md)
- **家校沟通总结**：单生聊天式个性化重写（学生档案「家校沟通」页签）+ 班级层批量生成，应用即写入学期评语，Agent 可自然语言发起（新增 `parent-summary` 工具）；机制见 [PARENT_SUMMARY.md](PARENT_SUMMARY.md)
- **系统提示词统一管理**：10 处 AI 系统提示词收敛为模块，新增 `/prompts` 页逐模块调整、恢复默认（见下文）
- **AI 通道宽容层**：OpenAI 兼容通道的网关响应宽容层（见下文）
- **数据层收敛**：`db.ts` 按域拆分为 `src/lib/db/`，门面公共 API 逐字不变；多表写操作改单批事务（`executeBatch`），消除半删/半改的不一致窗口；新增 SQLite 真通道自动化测试（模拟数据双通道等价对跑）；另有图表纵轴算法、导入对话框、表现时间线、月历组件等一批行为保持重构

兼容性：**无破坏性变更**。数据库结构仍是 v1.0.0 的迁移 1~9（30 张表），schema 零改动；本机存储仅新增键
`aprilio.prompts.v1`；导入/导出格式与 Agent 工具面只增不改（另为卡片导出新增 `dialog:allow-save`、
`fs:allow-write-file` 两条 capability 权限）。v1.0.0 用户运行新安装包覆盖安装即完成升级（identifier 与
v1.0.0 一致，安装器不触碰 `%APPDATA%` 数据目录，既有数据库/照片/背景/日志原样沿用），无需手工迁移数据。

### 系统提示词统一管理（2026-10-02）

应用内 10 处硬编码的 AI 系统提示词（助手主提示词、学期评语、评价报告、课堂小结、
推荐评语、备忘标题、监护人标签倾向、花名册姓名列识别、花名册班级推断、成绩单结构识别）
收敛为「提示词模块」，新增「提示词管理」页（`/prompts`）按分组逐模块调整、恢复默认。

- 兼容性影响：**无破坏性变更**。新增本机存储键 `aprilio.prompts.v1`，
  不改数据库、不改任何既有存储格式；历史版本没有该键 = 全部走内置默认。
- **零覆盖时行为与改造前逐字一致**：各模块的 `defaultText` 由改造前的硬编码文案原样搬入，
  并有测试用改造前导出的夹具逐字对账（`tests/fixtures/prompts-before.json` +
  `tests/prompt-wiring.test.ts`），确保升级不改变发给模型的内容。
- 设置页「模型方案 → 系统提示词」字段语义不变，仍是追加在助手主提示词末尾的全局补充设定
  （对应 `assistant.agent` 模块的 `{补充设定}` 占位符），与本页按模块精调互不覆盖。
- 机制与扩展方式见 [PROMPT_MANAGEMENT.md](PROMPT_MANAGEMENT.md)。

### 网关响应宽容层（2026-10-01）

OpenAI 兼容通道的响应处理放宽：网关在 200 成功体里把 `choices[*].message.role` 写成
空串时，先归一化为 `"assistant"` 再交给 rig 解析（原先会被 rig 的严格解码判为失败，
误报成 `ProviderResponseError: status 200 OK`，导致「设置 AI 保存未通过」）。

- 兼容性影响：**无破坏性变更**。只影响「成功但 role 不规范」这一类此前必然失败的响应，
  用户侧表现为原本存不下的 AI 配置现在能存下；归一化只在 role 缺失/空/空白时发生，
  其他响应字节级不变。数据库、本机存储、导入导出格式、Agent 工具参数语义均未改动。
- 实现与回归覆盖见 [AGENT_FRAMEWORK_EVALUATION.md](AGENT_FRAMEWORK_EVALUATION.md) §2.4。
