# 花名册导入

班级管理的第一步数据入口：把 Excel/CSV 花名册批量导入学生档案。
本文说明功能用法与设计要点（实现：`src/lib/roster.ts` + `src/components/ImportRosterDialog.vue`
+ Agent 工具 `import_student_roster`）。

## 入口

| 入口 | 行为 |
| --- | --- |
| 学生档案页「导入花名册」按钮（含空状态） | 打开导入对话框 |
| 班级管理页「导入花名册」按钮 | 跳到学生档案页并自动打开对话框 |
| 对 AI 助手说「帮我导入学生花名册」 | 助手打开导入对话框（智能导入模式），或经用户确认后由 `import_student_roster` 工具直接导入 |

## 两种模式

| 模式 | 适用 | 行为 |
| --- | --- | --- |
| **智能导入**（默认） | 任意表格 | 自动识别姓名列（规则打分 + 可选 AI 识别），其余列按表头关键词自动映射（学号/性别/出生日期/班级/监护人/电话/住址/备注），识别不了的列忽略 |
| **指定格式导入** | 标准模板 | 表头必须含「姓名」列，按表头精确映射；缺列时给出提示并提供模板下载 |

「下载模板」导出带 BOM 的标准 CSV（Excel 双击打开不乱码），表头：
姓名 / 性别 / 学号 / 出生日期 / 年级班级 / 身份证号 / 监护人 / 联系电话 / 家庭住址 / 备注。

## 文件格式与编码

- 桌面端支持 **XLSX / XLSM / XLSB / XLS / ODS**（Rust 端 calamine 解码为矩阵，取第一个
  非空工作表；日期单元格转 YYYY-MM-DD、整数单元格保持整数形态，选型见
  [EXCEL_PARSING_EVALUATION.md](EXCEL_PARSING_EVALUATION.md)）以及 **CSV / TSV / TXT**
  （UTF-8 优先、GBK 回退，桌面端由 `roster_read_text` 解码，上限 5MB，扩展名守卫与照片导入同一模式）
- 浏览器演示态仅支持 CSV/TSV/TXT（`<input type=file>` + TextDecoder），Excel 请用桌面端
- 分隔符嗅探（CSV）：`,` `\t` `;` `，` `|` 取首行出现最多者；支持引号包裹（含引号内换行与 `""` 转义）
- 表头嗅探：首行含「姓名/学号/性别…」等关键词即视为表头，否则按数据处理并生成「第N列」
  （CSV 与 Excel 两条通道共用同一份语义，格式解码在哪里做不影响识别逻辑）
- 跨列合并标题行自动跳过：表头行之前仅 1~2 个非空格的行按标题剔除（「XX中学2026级3班花名册」）；
  Excel 取第一个有数据的工作表（≥2 行），说明页/占位表在前不影响

## 姓名列识别（智能导入核心）

1. **规则识别**（永远执行，本地零成本）：
   - 表头精确命中「姓名/学生姓名/名字/学生/name」+60，包含命中 +45；命中排除词（学号/电话/日期/班级…）直接出局
   - 内容特征：2~4 个汉字且无数字标点的单元格占比（×40）、班级内近乎唯一（+10）、
     高重复率（-15）、数字占比高（-30）、长文本占比高（-20）
   - 得分 ≥60 置信度高、≥32 中、其余低
2. **AI 识别**（已配置模型时叠加）：把各列表头与最多 5 个示例值交给模型，
   只回 JSON `{column, confidence, reason}`；解析失败自动回退规则结果
3. **合成**：AI 选择与规则候选一致且 AI 自信 → 高；规则无正向信号的列无论 AI 多自信 → 低（必须人工确认）

置信度低时：对话框要求人工选择姓名列；Agent 工具不落库，返回候选列让模型向用户确认后带
`name_column`（列名或列号）重调。

## 成绩单检测与分流

花名册智能导入最常见的起点就是一份成绩单（姓名 + 各科分数列）。加载表格后会先做成绩单
识别（[docs/SCORE_IMPORT.md](SCORE_IMPORT.md)）：

- **对话框**：智能导入模式检测到科目列时展示横幅「这更像一份成绩单」，可一键
  「转为成绩导入」（已解析的表格原样交接给导入成绩对话框，含考试名/时间智能提取），
  或选择「仍按花名册导入」忽略提示
- **Agent 工具**：`import_student_roster` 检测到成绩单（置信度非低）时不导入花名册，
  转入成绩导入管道——自动建档 + 智能生成一次考试批次 + 成绩关联，回复中说明两件事都做了；
  置信度低时仍按花名册导入
- 表头嗅探剔除的标题行文本保留在 `RosterTable.titleText` 中，供提取考试名/考试时间，
  对花名册导入无影响

## 导入规则

- 姓名缺失 / 超过 20 字 / 表内学号重复的行不导入，逐行给出原因（单行失败不影响整批）
- 匹配键：`student_no` 优先；无学号时按「姓名+出生日期」兜底
  - 学号已存在且**姓名相同** → 用新上传的数据**覆盖更新**该记录（保留原记录 id，照片、表现记录等关联不受影响；监护人按新表整条覆盖），结果计入「更新」
  - 学号已存在但**姓名不同** → 跳过并提示「姓名不一致未覆盖」，避免把新学生覆盖到他人档案上
  - 无学号时命中「姓名+出生日期」→ 跳过（重复导入不产生重复学生）
- 无学号的行生成 `R<时间戳><序号>` 临时学号
- 性别归一化（男/M/male→男，女/F/female→女）；日期归一化（`2017.5.12`、`2017年5月12日` → `2017-05-12`）
- 状态一律写入 `active`（在读）

### 未命名批次自动分班（整批无班级信息）

- 整批行都没有班级（无班级列 / 全空）且不在班级详情页预设班级下导入时，不再并入虚拟「未分班」：
  全新的两批自动建成「未命名班级1」「未命名班级2」——导入两次即分成两个班，可在班级管理重命名。
- 重导入同一批（学号+姓名命中同一原班级）复用原班、不新建，存量学生的原班级不会被空值清空覆盖；
  追增（部分命中同一原班 + 部分新行）新行并入该原班；命中横跨多个原班时新行单立一个新班、存量各留原位。
- 对话框在预览区提示「将自动新建一个班级」，导入结果展示「已进入XX」并跳转到该班；
  Agent 工具在汇总中说明自动建班，并把班级元信息（年级/学期识别）落在新班上。
- 存量「未分班」为历史兼容保留：新导入不再写入，仅手动建档留空或历史数据会留在里面。

## Agent 行为

- **页面动作** `students/import-roster`：打开导入对话框（`args.mode` 可指定 `template`/`smart`，默认 smart），文件选择与导入确认由用户完成
- **工具** `import_student_roster`（dangerous，需 `confirm:true` 确认门）：
  1. `file_path` 缺省时弹出系统文件选择框；浏览器演示态明确报错
  2. 底层即智能导入管道（`runSmartImport`）——用户经 AI 助手导入与对话框导入行为一致
  3. 汇总回复：文件名、姓名列识别结果（方式+置信度）、成功/跳过/失败计数与明细样例

## 设计约束

- 解析与识别全部在前端（浏览器/桌面双态一致），Rust 只做文件读取（扩展名守卫，不开任意读权限）
- `roster_read_text` 是前端管道的内部 IPC 命令，不进 Agent 能力面（模型经工具间接使用）
- 日志只记计数与文件路径，不落学生姓名/电话等隐私字段
- 安装包体积：未引入任何前端解析库；Rust 侧 `encoding_rs` 与 reqwest 共用，增量≈0

## 验收清单

- [ ] 模板 CSV「下载模板」→ 填数据 → 指定格式导入成功，列表刷新
- [ ] 表头乱七八糟的 CSV（GBK 编码、分号分隔）智能导入可识别姓名列并导入
- [ ] **xlsx 直接导入**（含日期列、整数学号、跨列合并标题行）识别与导入正确
- [ ] 姓名列识别错误时可手动改列；低置信度有警示
- [ ] 重复导入同一文件（数据未变），第二次全部「更新」，学生总数与记录 id 不变
- [ ] 改动花名册中某学生的字段后重新导入 → 该学生档案被覆盖为新值；改姓名（学号不变）→ 跳过并提示姓名不一致
- [ ] 两份互不相交的未命名花名册各导入一次 → 建出「未命名班级1」「未命名班级2」两个班，不并入「未分班」；重导入其中一份 → 复用原班（更新计数，id 不变，不新建）
- [ ] 对助手说「帮我导入学生花名册」→ 打开导入对话框；确认后说「直接导入 <路径>」→ 走工具且首次调用被确认门拦截
- [ ] 选一份成绩单 → 出现「转为成绩导入」横幅；对助手直接给成绩单 → 自动生成考试并关联成绩（见 [SCORE_IMPORT.md](SCORE_IMPORT.md) 验收清单）
