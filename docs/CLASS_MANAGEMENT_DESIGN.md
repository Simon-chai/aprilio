# 班级管理功能设计（v0.1 草案）

> 状态：设计稿，未实现。本文回答两个问题：① 班级管理/人员管理的整体框架怎么搭；② 第一步「花名册导入」怎么做。

## 1. 现状盘点

aprilio 已有：

- `students` 表：姓名 / 性别 / 出生日期 / 学号（唯一）/ 年级班级（文本）/ 身份证号 / 监护人（单人）/ 电话 / 住址 / 状态 / 备注
- `photos` 表：学生 ID / 文件名 / 说明 / 拍摄日期
- 路由：`/home /classes /students /photos /profile /design /settings`
- 本地优先：SQLite + 不联网，浏览器演示态走内存数据

缺口：

- 没有班级实体（`grade_class` 是自由文本），无法承载「班级管理」
- 没有学段概念（小学/初中/高中的关注点差异无处安放）
- 监护人只支持一人（业界普遍做双家长）
- 没有成绩、日常表现、考勤的数据模型
- 没有任何批量导入能力，数据全靠手录

## 2. 业界调研

### 2.1 班主任智能工作台（离线单文件工具，与 aprilio 定位最接近）

一个 HTML 文件 + localStorage，27 个功能模块分 9 大板块：工作台仪表盘、学生档案、教学管理（成绩/作业/考勤/请假）、班级建设（量化积分/分组/座位表/课表）、健康安全（特异体质/晨检/突发事件）、家校协同（双家长通讯录/家访/家长会）、财务、效率工具、数据安全。

对我们最有参考价值的做法：

- **学生档案 = 花名册的升级版**：姓名学号、住走读、考勤率、成绩、班级排名、量化积分、预警标签一屏尽览；CSV 批量导入导出；双家长联系方式
- **成绩导入**：Excel/Word 表格直接上传，自动识别科目列（含自定义科目），自动创建考试并算排名；录入时按满分做校验
- **增值性评价**：以第一次考试为基线看进步幅度，「和自己比，更公平」
- **课堂表现**：点选学生 + 表现类型（积极发言/走神/违纪/主动帮助），一条记录秒完成
- **智能导入**：学生+成绩一张表，自动去重、自动分流；JSON 备份导入恢复 + 自动快照

### 2.2 班小二（微信小程序，家校沟通为主）

40+ 应用：私密成绩、表现评价、红花榜、班级相册、作业打卡、信息收集等。参考点：

- **私密成绩沉淀**：同一学科多年成绩带折线趋势，进步退步一目了然
- **班级相册**：AI 人脸识别把照片归档到具体学生名下——印证「照片按学生归档」是刚需，aprilio 的 photos 表已有雏形
- 大量功能靠**模板**降低录入成本

### 2.3 班级优化大师（希沃，课堂即时激励）

核心是学生积分点评体系：正面/负面行为标签、随机点名、小组竞赛、家长端同步。参考点：

- 日常表现的记录粒度是**事件**（学生 × 行为类型 × 时间 × 分值），而不是一段长文本——这是可统计、可画时间线的前提

### 2.4 对 aprilio 的四点启示

1. **记录颗粒度事件化**：表现、成绩都是「一条条记录」，学生详情页按时间线汇聚
2. **导入是数据入口的生死线**：班主任的数据都在 Excel 里，手录不现实；导入体验决定产品生死
3. **学生详情页是所有数据的汇聚点**：档案、成绩、表现、照片、家长，一人一页
4. **和自己比优先于排名**：本地单机工具没有年级横向数据，趋势/增值评价比排名更可行也更符合小学场景

## 3. 班主任关注哪些学生信息（按学段）

通用的信息分五层，学段决定每一层的具体内容：

| 层 | 小学 | 初中 | 高中 |
| --- | --- | --- | --- |
| 身份档案 | 姓名/性别/生日/学号/住走读/照片 | + 团籍、生源地 | + 选科组合、户籍 |
| 学业成绩 | 语数英道法科学体育；常见等级制；不排名 | 中考科目 9 门；及格率/优秀率；分层 ABCD | 语数英+3（3+1+2）；赋分、一本线 |
| 日常表现 | **习惯养成**：课堂发言、作业、劳动、礼貌；红花榜 | 纪律、违纪记录、量化积分 | 综合素质评价档案 |
| 健康安全 | **身高体重/视力**、特异体质、疫苗接种 | 心理健康、体质测试 | 心理健康、体检 |
| 家校联系 | 家长深度参与（沟通最频繁） | 家长会为主 | 学生自主为主 |

小学班主任的特点：科目少且常为等级制、不搞排名、重习惯轻分数、家长沟通频繁、图片记录多。这与 aprilio 现有的 photos 能力天然契合。

## 4. 信息架构

```
班级管理
├── 事务管理（本期只留入口，不做）
│   └── 预留：作业收缴、通知、班费、待办
└── 人员管理（本期重点）
    ├── 班级设置（学段、学年、科目配置）
    ├── 花名册（学生列表 + 批量导入/导出）   ← 第一步
    ├── 学业成绩（考试 × 科目 × 分数）
    ├── 日常表现（事件流：学生 × 行为 × 时间 ± 分）
    ├── 照片记录（已有，挂到学生名下）
    └── 学生成长档案（详情页改版：一人一页汇聚以上全部）
```

侧边栏调整：现有「班级」页改造为班级设置+花名册入口；「学生」列表保留；后续在详情页内聚合成绩/表现/照片。

## 5. 领域模型（SQLite 迁移草案）

```
app_settings   key TEXT PK, value TEXT            -- school_stage 等全局配置
classes        id, stage, grade, name, school_year, created_at
subjects       id, class_id, name, short_name, sort, full_score, is_enabled
exams          id, class_id, name, exam_date, type, note
scores         id, exam_id, student_id, subject_id, score, note
               UNIQUE(exam_id, student_id, subject_id)
guardians      id, student_id, relation, name, phone, note   -- 双家长
behavior_events id, student_id, occurred_at, category(positive/negative/neutral),
               tag, points, note, created_at
students（扩展） class_id, dorm(住走读), tags        -- grade_class 文本字段保留兼容
photos（不动）   已满足 MVP；后续可加 event 关联
```

要点：

- 科目做成**表**而不是枚举：学段、满分（等级制/百分制）、开停全部可配
- `scores` 按 (考试, 学生, 科目) 唯一，导入天然幂等
- 监护人拆独立表，向双家长演进；students 现有 guardian_name/phone 作为展示冗余
- 行为事件用 tag 字符串 + category，预设标签可配置，避免过早建枚举表

## 6. 学段配置机制

- 全局 `app_settings.school_stage`：`primary | junior | senior`，首次启动走设置向导
- 科目模板只做**初始值**，写入 `subjects` 后随时可改：
  - 小学：语文、数学、英语、道德与法治、科学、体育与健康、音乐、美术（默认启用语数英，满分 100，可切等级制）
  - 初中：语数英物化道法历史地理生物体育
  - 高中：语数英 + 物理/历史（二选一）+ 化学/生物/政治/地理（四选二，3+1+2）
- 界面按学段做差异：小学隐藏排名/及格率权重，突出红花榜与习惯标签；初中突出分层与及格率；高中突出选科与增值

## 7. 小学班主任 MVP 范围

| 优先级 | 功能 | 说明 |
| --- | --- | --- |
| P0 | 首次启动学段设置向导 | 选小学 → 预置科目 → 建班级 |
| P0 | **花名册批量导入** | 本文 §8，第一步落地项 |
| P1 | 成绩：单次考试导入 + 班级一览 + 学生趋势 | 和自己比（折线），不排名 |
| P1 | 日常表现事件 | 预设标签：课堂发言/乐于助人/作业进步/纪律提醒…±分，详情页时间线 |
| P2 | 照片关联表现事件、红花榜 | 在现有 photos 上轻量扩展 |
| P2 | 评语助手 | 衔接 ROADMAP 里的 AI 工具场景 |
| 不做 | 选科、赋分、复杂考勤、作业 | 小学阶段无此刚需 |

## 8. 花名册导入 MVP 详细设计（第一步）

> **2026-09 已落地**：指定格式导入 + 智能导入（姓名列自动识别，规则 + AI 双轨）+ Agent
> 工具/页面动作集成。实现说明与验收清单见 [docs/ROSTER_IMPORT.md](ROSTER_IMPORT.md)；
> 下文为原始设计稿（五步向导中的冲突逐条决策、错误 CSV 导出仍后置）。

入口：`ClassesView` / `StudentsView` 空状态 + 「导入花名册」按钮。

**文件格式**：CSV 优先（UTF-8 与 GBK 双编码探测，WebView2 的 `TextDecoder('gbk')` 支持）；Excel 后置（引入 xlsx 解析库需单独评估体积与离线约束）。同时提供「下载模板」导出标准 CSV。

**五步向导**：

1. **选择文件**：`@tauri-apps/plugin-dialog` 打开文件（浏览器演示态用 `<input type=file>`）
2. **列映射**：解析表头后自动嗅探（姓名/学号/性别/出生日期/监护人/电话…），每列可改映射或选「忽略此列」；允许无表头时手动指定
3. **预览校验**：逐行标记 —— 姓名缺失（错误）、学号表内重复（错误）、学号与库内已有重复（冲突）、电话格式（警告）、性别归一化（男/女/M/F → male/female）
4. **冲突策略**：对库内已有记录三选一 —— 全部跳过 / 覆盖更新 / 逐条人工决定；去重键 `student_no` 优先，无学号时用「姓名+出生日期」兜底
5. **结果报告**：成功 N / 跳过 M / 失败明细（可导出错误 CSV 修正后重导）

**工程原则**：

- 单行失败不影响整批；写入包在一个事务里
- 幂等：重复导入同一文件不产生重复学生
- 解析全部在前端 JS 完成，写库走现有 `db.ts` 封装（Tauri SQLite / 浏览器内存双态一致）
- 顺手把导入/导出做成 `src/lib/roster.ts`，成绩导入（M2）复用同一套「解析→映射→校验→冲突→落库」管道

## 9. 实施路线图

- **M1（1 周内）**：学段设置 + 班级实体迁移 + 花名册 CSV 导入/导出 + 模板下载
- **M2**：成绩导入（复用导入管道）+ 班级成绩一览 + 学生单科趋势
- **M3**：日常表现事件记录 + 详情页时间线
- **M4**：照片关联事件 + 红花榜 + 学生成长档案页改版
- **M5（远期）**：事务管理（作业/通知/班费）与评语助手

2. `grade_class` 文本字段与 `classes` 表的迁移策略：新数据写 `class_id`，旧数据启动时一次性归并或保留只读
