# 多模型自动切换（failover）

模型方案（设置中心 · AI 模型）可以存多套，但一次请求只会选中一套。本规则把「选中一套」升级为
「按顺序试到最后一套」：当前方案失败时自动改试其它已配置方案，成功后把当前方案持久切过去。

全自动、无开关：所有 AI 调用默认经过 `src/lib/ai-failover.ts`，不做任何配置项。

## 行为规则

| 场景 | 行为 |
| --- | --- |
| 候选顺序 | 当前方案 → 其它已配置方案（按设置页列表顺序）；缺模型 / 缺密钥的方案不参与 |
| 单次失败（网络、限流、额度、密钥、404、超时…） | 自动改试下一个候选，直到成功或候选耗尽 |
| 成功的是备用方案 | 把「当前使用」持久切到该方案（切换胶囊即时刷新），直到用户手动切回 |
| 失败方案 | 进入冷却（默认 5 分钟），冷却期内不进入备用顺序；到期自动恢复 |
| 当前方案 | 永远排第一：用户手动选的模型不会被冷却挡住 |
| 已输出流式增量后失败 | **不切换**，原样报错：换模型会让半截文本与新回复错乱 |
| 参数 / 协议类错误（序列化、字段缺失） | **不切换**，换模型同样会失败，直接抛错 |
| 全部候选失败 | 抛聚合错误「已自动尝试 N 个模型方案，全部失败：首个原因」；当前方案不变，避免在不可用模型间来回跳 |

## 超时

Rust 侧请求没有超时，模型完全无响应会一直转圈。由前端补两道闸（只放弃本次候选，底层请求无法取消）：

| 类型 | 默认上限 | 说明 |
| --- | --- | --- |
| 流式（有 `onDelta`） | 90 秒 | 只等**首个增量**；首字到达后不再限时，长回答不受影响 |
| 非流式（`chatOnce` / 导入识别） | 4 分钟 | 整次请求上限 |

超时按「本次失败」处理，进入自动切换；迟到的事件被丢弃，不会重复推给界面。

## 接入点

`createFailoverLlm()` 是唯一包装入口，以下链路缺省都走它（单测注入 `llm` 时不包装，保持替身行为）：

| 链路 | 位置 |
| --- | --- |
| 通用生成任务（评语 / 家校总结 / 表现 / 备忘 / 报告 / 课堂摘要 / 记忆） | `src/lib/ai-run.ts` `runAiTask` |
| 裸 chat（成绩单识别、花名册识别） | `src/lib/ai-run.ts` `chatOnce` |
| 文本润色 | `src/lib/polish-ai.ts` |
| Agent 对话（多轮 tool loop） | `src/agent/providers/index.ts` `createLlm` |

不接入：`verifyAiConfig`（校验的必须是用户正在编辑的那一套）、`listAiModels`（拉模型列表）。

## 存储与兼容

- 冷却表：`localStorage["aprilio.ai.failover.v1"]` → `{ cooldowns: { [profileId]: 到期时间戳 } }`
- 新增键，不改 `aprilio.ai.profiles.v1` / `aprilio.ai.config` 结构；旧数据直接可用，删掉该键只失去冷却记忆
- 冷却表读取时顺带清理过期项，不会无限增长

## 验收

`tests/ai-failover.test.ts` 覆盖：候选顺序（当前优先、缺密钥跳过）、失败切换并持久化、成功不切、
冷却期内跳过与到期恢复、手动切回优先、流式已输出不切换、参数错误不切换、首字超时与整次超时、
全部失败的聚合文案、无方案时使用调用方配置。
