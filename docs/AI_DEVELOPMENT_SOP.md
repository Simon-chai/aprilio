# AI 研发 SOP（全 AI 开发与测试体系）

面向 AI 开发者 / 协作 Agent 的标准化作业流程。目标：AI 参与的开发与人工开发同质，
每次变更都被自动验证、可防退化。**流程按序执行，验证门禁不豁免。**

## 流程总览

| 阶段 | 关键动作 | 产物 / 门禁 |
| --- | --- | --- |
| 1. 需求澄清 | 边界界定，不改产品意图先问清 | 需求边界一句话确认 |
| 2. Spec 驱动 | 复杂需求先写 spec/tasks 再动码 | spec 文档 |
| 3. TDD 先行 | 先写失败测试再实现 | 失败测试 → 转绿 |
| 4. 实现与约束 | 遵守架构 / 体积 / 隐私红线 | 符合约束的代码 |
| 5. 验证门禁 | typecheck → test（动 Rust 加 cargo check） | 全绿输出 |
| 6. 防退化评测 | Agent 行为变更补 Evals 用例 | 黄金集全通过 |

## 1. 需求澄清与边界界定

- **不改产品意图先问清**：需求模糊、有多种合理解读、或涉及产品行为取舍时，
  先向用户确认再动码，不要替用户做产品决策。
- 动手前明确三件事：改什么、**不改什么**、怎么算完成（验收标准）。
- 过程中发现边界外的问题（「顺手就能修」的诱惑）：单独提出，经确认后再做，
  不混入本次变更。

## 2. Spec 驱动

- **复杂需求先写 spec/tasks 再动码**：新功能、跨 TS/Rust 两层的改动、
  改变既有行为的重构，都属于复杂需求。
- spec 要素：背景与目标、非目标（明确不做什么）、方案要点、任务拆解、验收清单；
  文风对齐 docs/ 下现有文档（简洁中文、表格与清单为主）。
- 简单需求（一两个文件、行为不变）可直接做，但验证门禁不豁免。

## 3. TDD 测试先行

- **新能力先写失败测试再实现**；修 bug 先写能复现的失败测试再修。
- 测试框架：TS 侧统一 vitest；Rust 侧 cargo test / cargo check。
- Agent 能力测试分两层：
  - 工具层：参考 `tests/agent-*.test.ts`（工具执行、确认门、注册表）；
  - 意图层：`tests/evals/`（见第 6 节）。
- mock provider（`src/agent/providers/mock.ts`）可在不联网的情况下
  走通「理解 → 调工具 → 回喂 → 总结」全链路，测试优先复用它或注入脚本化 fake LLM。

## 4. 代码标准与架构约束

| 约束 | 内容 |
| --- | --- |
| 架构分层 | 循环在 TS（`src/agent/loop.ts`）；LLM 协议转换在 Rust（`src-tauri/src/ai.rs`）；能力容器（`src/agent/container.ts`）是唯一事实源，改前先读 [docs/AGENT.md](AGENT.md) |
| 新增能力 | `src/agent/tools/` / `src/agent/page-actions/` 放文件即被扫描装载，不改 registry、不改 useAgent、不改清单文件 |
| 安装包体积 | 10MB 硬约束：新增依赖先评估体积（先例：LanceDB 因依赖树 +25MB 被否，换 SQLite 自实现） |
| 隐私 | API 密钥只存本机；工具返回会进入 LLM 上下文，云 API 场景的脱敏开关落地前不得默认开启敏感字段；日志不记录密钥与学生敏感原文 |
| 语言 | 注释、提交信息、面向用户的文案一律中文 |

## 5. 变更验证门禁

完成任何变更前，按序执行并确认全绿：

```
npm run typecheck        # 必须
npm test                 # 必须
cargo check --manifest-path src-tauri/Cargo.toml   # 动了 Rust 才需要
```

- **全绿才算完成**；向用户报告结果必须附真实命令输出，禁止凭感觉宣称通过。
- 测试失败时先读懂失败原因（区分「实现错了」与「测试该更新」），不靠删断言转绿。

## 6. 防退化评测（Evals）

Agent 的自然语言理解层没有类型检查可依，靠黄金用例集防退化：`tests/evals/`。

| 文件 | 职责 |
| --- | --- |
| `dataset.ts` | 黄金用例集（数据表驱动：`input` → 期望 `tool` / `args` 断言），**加用例只加数据** |
| `eval-runner.ts` | 单例执行与统计（工具命中率、参数匹配、确认门拦截） |
| `agent-evals.test.ts` | 全量基准 + 分类别断言 + runAgentTurn 端到端评测 |

覆盖场景：页面跳转（navigate）、数据查询（query_data）、文档检索（find_docs）、
写操作确认门（ui_action/dangerous 工具必须先拒后 confirm）、未知工具兜底（不崩溃、错误回喂）。

**防退化红线**（任何一条被破坏都视为阻断性变更，必须修复后才能交付）：

1. 意图命中率下降：黄金用例集要求 100% 通过；
2. 确认门被绕过：dangerous 工具 / 写操作页面动作未带 `confirm:true` 时必须被拦截；
3. 未知工具导致循环崩溃：错误必须以 tool 消息回喂，循环继续。

新增或修改 Agent 相关行为（工具、prompt、mock 规则、循环逻辑）时，同步补 Evals 用例。
