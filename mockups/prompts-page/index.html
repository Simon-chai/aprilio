提示词管理 · 改版样稿

三版都基于同一套真实数据（src/prompts 全部 10 个模块）与应用设计 token，可直接点选模块、编辑正文、保存、恢复默认（仅前端演示，内存态）。 差别在「模块导航」的组织方式——这是这页样式好坏的关键。

方案 A

分组 Tab + 模块轨道

模块导航全部压进顶部两条横带：分组 Tab（能量线选中态）+ 模块胶囊横排。纵向空间全部让给编辑区，模块一眼可见、单点即切。

  • 切换最快，模块在哪最直观
  • 变量 / 预览收进右侧分段器，少一层卡片
  • 模块多时轨道横向滚动 + 搜索兜底
打开方案 A
方案 B

分组筛选 + 模块列表

左侧列表常驻（主从布局），分组从三张卡片收敛为一段分段器，列表变扁平紧凑行；右侧放弃卡片堆叠，改为单画布分区编辑，模块头吸顶。

  • 最耐扩展：模块翻倍列表也不乱
  • 「全部」视图保留分组语境
  • 信息密度最高，操作都吸顶常在
打开方案 B
方案 C

沉浸编辑 + 模块切换器

不做常驻列表，编辑视野最大化；「看模块」收进一个醒目的「切换模块」按钮（展开分组搜索面板），配合上/下一模块与 ←/→ 快捷键。

  • 当前模块存在感最强
  • ←/→ 秒切、Esc 关面板
  • 变量 / 预览折叠收纳，默认最简
打开方案 C

共同保底：三版都保留了现有页的全部能力——分组化模块列表、已自定义标识、变量插入（点变量名落光标处）、 契约变量只读展示、未知占位符告警、未保存提示、单模块 / 全部恢复默认、与运行期同语义的预览。 差别只在组织与视觉密度，定稿后按所选方案改造 PromptsView.vue。
